# CL Release 5 — controlled rollout of migration `20261126120000`

`20261126120000_champions_league_relax_resultless_legacy_conversion.sql` is the
only database change in CL Release 5. It `CREATE OR REPLACE`s the **private core**
`apply_champions_league_league_phase_validated_core_v1` to allow converting a
resultless legacy tournament (≤ 1 group, `competition_format IS NULL`) to
Champions League with explicit replace confirmation. Every other guard is
byte-identical; the public wrapper and same-club fail-safe are untouched.

> Status: **not applied to any database.** No production write was performed
> while preparing this. Apply only after your separate approval.

## 1. Read-only production prerequisite check (operator runs with prod access)

Run these **read-only** queries against production before applying. They change
nothing. Expected results noted inline.

```sql
-- (a) The private core the migration replaces must already exist (created by the
--     2026-11-25 remediation 20261125190218). Expected: one row.
SELECT p.oid::regprocedure AS signature
FROM pg_proc p
WHERE p.oid = to_regprocedure(
  'public.apply_champions_league_league_phase_validated_core_v1(uuid,timestamptz,integer,integer,boolean,boolean,jsonb)'
);

-- (b) The public wrapper must exist and stay the only granted entry point.
--     Expected: wrapper present; core has NO grant to authenticated.
SELECT p.proname,
       has_function_privilege('authenticated', p.oid, 'EXECUTE') AS authenticated_execute
FROM pg_proc p
WHERE p.oid = ANY (ARRAY[
  to_regprocedure('public.apply_champions_league_league_phase(uuid,timestamptz,integer,integer,boolean,boolean,jsonb)'),
  to_regprocedure('public.apply_champions_league_league_phase_validated_core_v1(uuid,timestamptz,integer,integer,boolean,boolean,jsonb)')
]);
-- Expected: wrapper authenticated_execute = true, core authenticated_execute = false.

-- (c) Current core still carries the strict guard (proves we are replacing the
--     expected body). Expected: 1.
SELECT count(*) AS has_unsafe_guard
FROM pg_proc p
WHERE p.proname = 'apply_champions_league_league_phase_validated_core_v1'
  AND p.prosrc LIKE '%UNSAFE_LEGACY_CONVERSION%';

-- (d) Impact scope: how many non-archived tournaments are the resultless legacy
--     single-group shape this migration newly allows to convert. Informational.
SELECT count(*) AS convertible_legacy_single_group
FROM public.tournaments t
WHERE t.competition_format IS NULL
  AND t.archived_at IS NULL
  AND (SELECT count(*) FROM public.tournament_groups g WHERE g.tournament_id = t.id) <= 1
  AND NOT EXISTS (
    SELECT 1 FROM public.tournament_matches m
    WHERE m.tournament_id = t.id
      AND (m.phase = 'knockout' OR m.status IN ('live','completed')
           OR m.home_score IS NOT NULL OR m.away_score IS NOT NULL)
  );
```

If (a) returns no row, **do not apply** — apply the 2026-11-25 remediation first.
The migration also guards this itself and aborts with a clear error.

No existing tournament is modified by the migration itself — it only changes
function logic. Conversions happen only when an admin explicitly applies a
Champions League plan with confirm-replace.

## 5. Rollback

Forward-only revert: `CREATE OR REPLACE` the core back to its pre-Release-5 body.
That body is the function definition in
`20261122180000_apply_champions_league_league_phase.sql` (identical except the
function name is `..._validated_core_v1`). A revert migration can be generated by
the same transform used to create this one, restoring the `UNSAFE_LEGACY_CONVERSION`
block and the `phase = 'group'` cleanup. The wrapper and grants need no change.
Because the migration changes only function logic (no data, no schema), rollback
is safe at any time and does not touch tournament rows.
